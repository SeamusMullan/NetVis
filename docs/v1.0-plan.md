# NetVis v1.0 — the road to 1.0

> Status: **in flight** (updated 2026-08-10). Supersedes the feature-backlog half of
> `docs/v0.6.x-roadmap.md` (its #13–#62 backlog is now all shipped across the
> v0.6→v0.9 arcs; its **non-goals** table remains authoritative except where this
> doc explicitly overrides it — see Pillar 6). **v0.9.1 is released (Latest)**,
> draining the Diff + format-panel half of Pillar 1 (#33/#35/#37/#44/#45); the
> Inspector half (#49/#50) and the two deepest Diff items (#34/#36) split out to
> **v0.9.1b**. The rest of the v0.9.x arc below stages the work, v1.0.0 is the
> capstone.

v1.0 is not "drain the last 10 issues." 1.0 is a **statement**: NetVis is
feature-complete against its main competitor (Netron), **fast** on the models it
claims to open, **polished**, and **stable enough to promise API/ABI/format
guarantees**. Six pillars, staged as themed point releases (the proven v0.9.0-arc
pattern), then a v1.0.0 capstone that verifies the whole.

The through-line that must survive 1.0 unbroken: **the zero-payload thesis**
(structural parse never reads tensor bytes; the single decode job is the only
payload reader) and the **single static binary** (no runtime deps, WASM-sandboxed
plugins). Every item below is checked against both.

---

## Competitive frame — parity with Netron

Netron (github.com/lutzroeder/netron, MIT, ~33k★) is the reference model viewer and
NetVis's main competitor. Honest scorecard:

**Where NetVis already meets or beats Netron today:**
- Graph view (pan/zoom/LOD, collapse groups for repeated blocks — Netron's
  subgraph expand is coarser), node→properties, search, PNG export, dark theme,
  multi-model tabs, command palette.
- **NetVis-only:** the cost/FLOP **analyzer** + roofline + latency estimate; the
  **zero-payload** instant open of multi-GB models (Netron loads weights); the
  **WASM plugin** system; the **headless report CLI**; per-channel/outlier weight
  stats; the whole v0.8/v0.9 QoL+analyzer cluster.

**Where Netron is ahead — the parity gaps (this is Pillar 5's job):**
- **Formats NetVis lacks entirely:** TensorFlow (SavedModel / frozen `.pb` /
  `.meta`), Caffe (`.caffemodel`/`.prototxt`), Darknet (`.cfg`/`.weights`).
- **PyTorch depth:** Netron reads `torch.export`, ExecuTorch, and **full
  TorchScript graphs**; NetVis ships a TorchScript op *inventory* only (#40), not a
  compute graph.
- **Experimental formats Netron has:** MLIR, JAX, RKNN, ncnn, MNN, PaddlePaddle,
  scikit-learn. (Parity-*nice*, not parity-*critical* — most are niche.)

**Parity definition for v1.0:** match Netron on the **full-support** formats a
mainstream user hits (TensorFlow, TorchScript-as-graph, Caffe, Darknet) and keep
NetVis's analyzer/zero-payload/plugin lead. The long experimental tail is a
post-1.0 "coverage via plugins" story (the parser host API + WASM ParserPlugin
already exist — a format can ship as a plugin without a core release).

## The six pillars

### Pillar 1 — Feature-complete (drain the backlog)
Close every open non-Nexus issue so the "features" story is done.
- **Inspector:** #49 GGUF single-block dequant preview (view-only, behind the one
  decode job — NOT a plugin, per the thesis), #50 cross-model same-tensor compare
  (needs DiffLoader to expose its MappedFile/dir + a 2nd decode path). *(v0.9.1b)*
- **Diff maturity:** ✅ #33 summary panel (added/removed/changed + clickable list),
  #34 per-tensor weight-stat diff *(v0.9.1b)*, ✅ #35 match-by-name vs
  match-by-topology toggle, #36 3+ model comparison (A/B/C quant ladder)
  *(v0.9.1b)*, ✅ #37 export change report (md/TSV).
- **Format panels:** ✅ #44 GGUF metadata (KV) panel (arch/quant/rope), ✅ #45
  detection confidence / reason in the status bar.

**Status:** shipped in v0.9.1 — #33, #35, #37, #44, #45. Remaining in **v0.9.1b** —
#49, #50, #34, #36 (the four that need a second decode path / N-way diff state, i.e.
the ones with real engine work behind them rather than panel work).

### Pillar 2 — Optimization (the "opens anything, fast" proof)
NetVis claims instant multi-GB open + smooth 100k-node graphs. 1.0 must *measure*
and *defend* that. There is **no perf harness today** — that is the first task.
- **P2.1 Benchmark + perf-regression harness** (foundational; do first): a
  headless `netvis --bench` (or a bench test target) timing parse, shape-infer,
  layout, cost, and a synthetic-frame render cost across a fixture ladder
  (1k/10k/100k nodes); emits JSON; a CI gate flags a regression beyond a threshold.
- **P2.2 Layout speed:** profile `compute_layout` on 100k display nodes; the
  Sugiyama passes (ordering/coordinate) are the suspects.
- **P2.3 Render:** draw-call batching, LOD threshold tuning, cull-cost audit; the
  recurring per-frame cache/alloc findings from `/simplify` folded into a
  systematic sweep (the `activation_liveness_curve` per-frame rebuild flagged in
  v0.8.3 is a known one).
- **P2.4 Parse/startup:** cold-open profile; mmap + intern + collapse-detect timing.
- **P2.5 Memory:** peak-RSS ceiling check on the fixture ladder; no per-frame heap
  in hot paths (enforce via the harness).

### Pillar 3 — QoL / polish ("feels finished")
- **P3.1 Unified Preferences window** — prefs are scattered menu toggles +
  `view_prefs.json` today; one Settings panel (theme, layout, heatmap, edge
  routing, plugin trust, machine profiles) with reset-to-default.
- **P3.2 Session / workspace restore** — reopen last tabs + camera on launch (opt).
- **P3.3 Keyboard-nav + a11y pass** — full keyboard reachability, focus rings,
  colorblind-safe category palette option, font scaling.
- **P3.4 Empty-state / onboarding** — first-run hint, drag-drop affordance, sample
  model links (Netron ships samples — match this).
- **P3.5 View-state undo/redo** — collapse/nav/selection history beyond #17.

### Pillar 4 — Stability / 1.0 commitments (what "1.0" *promises*)
- **P4.1 Plugin ABI freeze + guarantee** — Op/Parser/Pass ABIs are at v1; document
  the compatibility promise, add a version-negotiation/rejection test, freeze the
  SDK header surface.
- **P4.2 Format-support matrix + honesty audit** — a documented table (format →
  graph? weights? shapes? known gaps) and an audit that every "honest unknown"
  path is actually honest (no fabricated shapes/FLOPs).
- **P4.3 User guide** — real docs (open a model, read the analyzer, write a plugin,
  use the CLI) beyond the README.
- **P4.4 Diagnostics** — a log surface + graceful crash/last-error reporting
  (currently silent-best-effort everywhere).
- **P4.5 Close test-coverage gaps** — the documented ones (view-layer harness was
  #5; audit for others), plus fuzz the new parsers.

### Pillar 5 — Built-in coverage (Netron format parity)
Bounded structural readers (zero-payload, in the core), sequenced by user value:
- **P5.1 TensorFlow** — SavedModel (`saved_model.pb` + variables) + frozen `.pb`
  (GraphDef). Biggest single gap; protobuf like ONNX, so the hand-rolled wire
  reader pattern applies.
- **P5.2 TorchScript full graph** — upgrade #40's op inventory to a real compute
  graph (bytecode + type tables). Large; may itself be a mini-arc.
- **P5.3 Caffe** — `.prototxt` (text) + `.caffemodel` (protobuf).
- **P5.4 Darknet** — `.cfg` (INI-ish) + `.weights` (flat binary).
- **P5.5 torch.export / ExecuTorch** — the newer PyTorch export graph.
- *(Experimental tail — MLIR/JAX/RKNN/ncnn/MNN/Paddle/sklearn — explicitly
  post-1.0, and prime WASM-ParserPlugin candidates rather than core parsers.)*
Each parser: Detect entry + bounded reader + fixtures + the honesty rules (record
offset+len, never decode; unresolved dim ⇒ honest-unknown).

### Pillar 6 — View-panel plugins *(overrides the roadmap non-goal)*
The v0.6.x roadmap marked custom view-panel plugins **"revisit post-1.0"**; per
this planning round they are **IN v1.0**. Scope: a **declarative UI-description
protocol** over the existing WASM boundary — a plugin emits a widget tree (labels,
tables, plots, buttons bound to host actions), the host renders it in ImGui. This
keeps the sandbox + single-binary + zero-payload invariants (a panel plugin gets
the same capability-gated host API — no raw byte access, no native code). Explicit
non-goal still: native `.so`/`.dll` panels. This is the largest single design in
the arc and gets its own point release + freeze.

## Staged arc (proposed)

Themed point releases, smallest/least-risky first, each shippable + tagged; v1.0.0
is the capstone that adds the stability commitments + a full parity pass.

| Release | Theme | Contents |
|---|---|---|
| **v0.9.1** ✅ | Diff + format panels (Pillar 1, part 1) | #33, #35, #37, #44, #45 — *released 2026-07-29* |
| **v0.9.1b** | Inspector + deep Diff (Pillar 1, part 2) | #49, #50, #34, #36 — drains the rest of the backlog |
| **v0.9.2** | Optimization (Pillar 2) | P2.1 bench harness FIRST, then P2.2–P2.5; **wall-clock perf-regression CI gate** (decided: generous threshold to tolerate shared-runner noise — see below) |
| **v0.9.3** | QoL / polish (Pillar 3) | P3.1–P3.5 |
| **v0.9.4** | Format parity (Pillar 5, ALL) | P5.1 TensorFlow + P5.3 Caffe + P5.4 Darknet (protobuf/text) **and** P5.2 TorchScript full graph + P5.5 torch.export/ExecuTorch (PyTorch depth) — decided: ship together. Largest release; may internally sub-stage. |
| **v0.9.5** | View-panel plugins (Pillar 6) | the declarative UI-description protocol + a freeze |
| **v1.0.0** | **Capstone** (Pillar 4 + parity verification) | ABI freeze, format-honesty matrix, user guide, diagnostics, test-gap closure, a documented Netron parity scorecard, final polish |

Sequencing rationale: Pillar 1 drains known work (low risk, momentum). Pillar 2's
harness lands **before** the parsers (Pillar 5) so their perf is measured as they
land — and its CI gate then guards every subsequent release. QoL (3) is
independent. Format parity ships as ONE release (decided) covering both the
protobuf/text readers (TF/Caffe/Darknet) and the PyTorch depth (TorchScript
full-graph/torch.export) — it is the largest and will likely sub-stage internally
(freeze the IR-mapping contract, fan out one parser per agent). View-panel plugins
(6) come late — they build on a stable plugin ABI, which 1.0 then freezes. The
capstone is deliberately commitments-only so it can't slip on feature work.

This is **6 releases** (5 point + the v1.0.0 capstone). A genuine 1.0 program, not
a sprint — but each release is independently shippable (the arc pattern), so value
flows continuously and the plan can be re-scoped between releases.

**Decided (this planning round):**
- Format parity I+II ship in ONE release (v0.9.4), not split.
- Perf-regression is a **CI gate** (P2.1), not just local: wall-clock timing in CI
  with a **generous threshold** (e.g. flag only >25–30% regression vs a committed
  baseline) so shared-runner variance doesn't cause flaky failures; the baseline is
  re-committed intentionally when a real change moves it. Median-of-N runs to
  damp noise.
- Cadence kept at ~6 staged releases (view-panel plugins stay in 1.0).

## Non-goals for v1.0 (carried from the roadmap, still true)
- Native `.so`/`.dll` plugins (even with Pillar 6's panels — those stay WASM).
- Dequantization/payload-transforming **plugins** (the zero-payload thesis; #49 is
  a host view-only preview, not a plugin capability). The README's original blanket
  non-goal "no dequantization of GGUF quant blocks" is **narrowed** for 1.0: it
  scopes to *transforming or exporting* dequantized payload. A bounded, opt-in,
  view-only single-block preview inside the existing one decode job is permitted —
  it reads no more bytes than the inspector already reads and produces no artifact.
- WASI/syscalls in the sandbox; wasmtime backend (wasm3 stays unless a speed need
  proven by the Pillar-2 harness justifies the runtime-agnostic swap).
- General XML/HDF5 parsers (bounded per-format readers only).
- The experimental-format long tail as **core** parsers (they are WASM-ParserPlugin
  candidates post-1.0).
- Nexus #67 stays in its own milestone — orthogonal to the parity/QoL story.

## Resolved (this planning round)
1. **Cadence:** ~6 staged releases (5 point + v1.0.0 capstone). Kept, not compressed.
2. **Format priority:** ship ALL parity formats in one release (v0.9.4) — no
   TF-vs-TorchScript-first split.
3. **View-panel plugins:** IN v1.0 (Pillar 6), overriding the roadmap's post-1.0
   default.
4. **Perf gate:** CI wall-clock gate with a generous threshold + median-of-N
   (P2.1), not local-only.

## Resolved (2026-08-10 — issues now filed, milestones live)
5. **v0.9.4 split:** held as **one tag**, sub-staged internally (freeze the
   IR-mapping contract first, then one parser per agent). The v0.9.1 → v0.9.1b split
   is the precedent for the escape hatch: if a release proves too large mid-flight,
   ship the finished part on the planned tag and move the remainder to a `b`
   milestone rather than holding the whole release. No pre-emptive split.
6. **Nexus #67:** stays **fully separate** in its own milestone (consistent with the
   non-goals table). It is a workspace/manifest index view, not a model-format
   parser, so it shares no IR-mapping work with v0.9.4 and must not gate it.
