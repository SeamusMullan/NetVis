## Verified and safe

- **#122** (barycenter rollback) is complete, tested and committed — the test was
  proven non-vacuous by reverting the fix and watching it fail on real numbers
  (crossings 18→21, 15→19, 22→25). `LayoutCache::kVersion` bumped 4→5.
- **#103 session store** links and passes: 330 cases / 7542 assertions.
- **A real crash was found and fixed in shipped code**: `nlohmann`'s `dump()`
  uses the strict UTF-8 handler and throws on invalid sequences, and
  `App::save_recent` dumps raw filesystem paths — which on Linux are bytes with
  no encoding guarantee. Opening a file with such a path terminated the app.
  Fixed at all three dump sites with `error_handler_t::replace`.

## NOT done — do not assume any of this works

1. **Nothing is wired into `App.cpp`.** No menu entries, no calls to
   `draw_preferences_panel` / `draw_empty_state` / `draw_shortcuts_window`, no
   Ctrl+Z/Ctrl+Y handlers, no `record_view_history()` call, no session
   save/restore on launch/exit. The five features are written but unreachable.
2. **`App.h`'s new methods are declared but undefined**: `record_view_history`,
   `undo_view`, `redo_view`, `save_session_now`, `restore_last_session`,
   `category_style_for`. The GUI target will **fail to link** until the lead
   implements them.
3. **`tests/test_view_history.cpp` is the pre-split mirror test.** It duplicates
   the ring-buffer algorithm in a local `MiniHistory` because the header used to
   be unreachable. The lead has since split the real ring into
   `engine/ViewSnapshot.{h,cpp}` inside `netvis_core`, so the test must be
   rewritten against the real type. It also hard-codes `kMirrorMax = 64`, which
   can drift from `kMaxHistoryEntries`.
4. **`tests/test_category_style.cpp` verifies nothing today.** It is gated on
   `__has_include("imgui.h")`, which is false for `netvis_tests`, so it reports
   one skipped case. It is inert by design (it will not break the build) but it
   is not coverage. The agent's recommended fix is an `imgui_headers` INTERFACE
   target plus compiling `CategoryStyle.cpp` into the test executable — see its
   report; do **not** put it in `netvis_core`, which must stay GUI-free.
5. **The tree has not been built since the ViewHistory split.** Assume red.

## Decisions already made (do not relitigate)

- **#104**: colour alone cannot carry 15 op categories for a colourblind viewer,
  so accessible mode pairs an Okabe–Ito palette with a non-colour border cue.
  8 hue slots, reused semantically, disambiguated by pattern. A `static_assert`
  in `CategoryStyle.cpp` enforces that no two categories share both.
- **#106**: undo covers everything including the camera (user's call), with
  camera-only changes coalesced so one drag is one undo step.
- **#103**: opt-in and off by default; collapse state deliberately not stored.
- **#102**: additive — menu items stay; reset is per-section; plugin enablement
  is excluded from every reset because it is a trust decision.
- **#105**: sample models are copyable links, never downloads. ImGui 1.92.8 does
  ship `TextLinkOpenURL` backed by a shell-exec, but enabling it needs explicit
  sign-off — it is a shell-exec in a product that promises no network access.

## Open items raised by agents, still unaddressed

- **Real bug, unfixed**: `App::load_view_state` (`App.cpp` ~1062-1088, #56) can
  `push_graph` into a different graph and then claim `nav->owner_generation/
  owner_graph` for it, suppressing the cross-graph wipe — but only `path_a`/
  `path_b` are restored, so `nav->pinned`, `focus_hist` and `bookmarks` still
  hold IR indices from the **previous** graph. This is the recurring stale-IR-
  index class. Worth its own issue.
- **Engine gap**: there is no public `ModelSession::request_relayout()`. Both
  #106 and #103 need one; `ViewHistory` currently works around it by staging all
  but one collapse bit via `set_expanded_state()` then flipping the last through
  `session.toggle_group()` so exactly one re-layout is requested.
- **`App::category_color` is now a duplicate** of `category_style(c, dark,
  false)`. Two palettes that will silently drift; collapse to one.
- **`save_prefs`/`load_prefs` do not serialize** `accessible_palette`,
  `ui_scale`, `restore_session`. They work live but will not survive a restart.
  Clamp `ui_scale` to 0.75–2.0 on load.
- **App version is not reachable from C++**. `NETVIS_VERSION` is CMake-only. The
  About box says so honestly rather than inventing a string. One line fixes it:
  `target_compile_definitions(netvis PRIVATE NETVIS_VERSION_STRING="${PROJECT_VERSION}")`.
- **`App::open_file_dialog` advertises 7 filters** but the parsers support
  OpenVINO `.xml`, CoreML `.mlmodel`/`.mlpackage`, Keras `.h5`/`.keras` and
  NumPy `.npz` too. A user with one of those sees an empty dialog.
